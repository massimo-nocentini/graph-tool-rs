Expand description

Optional (source, target) -> edges index.

One table keyed on the ordered pair, replacing vector<gt_hash_map<Vertex, vector<Vertex>>> (graph_adjacency.hh:624) – one hash table object per vertex, keyed by the source only.

The asymmetry is what causes the second confirmed defect: remove_vertex_fast (:1471-1535) patches _ehash only through out_edges(back) and out_edges(v), so a neighbour u that held back as a target keeps a key naming a dead vertex, and edge(u, v, g) afterwards returns false. With no privileged endpoint there is no direction a relabelling can forget.
