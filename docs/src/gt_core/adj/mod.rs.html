1//! Adjacency storage: the `boost::adj_list` replacement.
2//!
3//! One contiguous `Vec<AdjEntry>` per vertex, out-entries in `[0, out_len)`
4//! and in-entries in `[out_len, len)` -- the same layout as
5//! `graph_adjacency.hh:222`, at half the width. Edge indices are dense, via a
6//! free list, so edge property maps stay compact.
7//!
8//! Mutation goes through exactly two private primitives, `splice_in` and
9//! `splice_out`, and every entry relocation is reported as a [`Moved`] value.
10//! graph-tool instead declares every mutating free function a `friend`
11//! (`graph_adjacency.hh:755-818`), so `_n_edges`, `_epos` and `_ehash` are
12//! effectively public and each mutator re-derives the invariants by hand --
13//! which is how `clear_vertex` comes to decrement `_n_edges` by two for one
14//! removed edge (`:1404-1413`).
15

35/// The default graph: dense edge indices, O(1) endpoint lookup, no `(s,t)`
36/// hash index. Corresponds to graph-tool's `_keep_epos = true`,
37/// `_keep_ehash = false`.
38pub type Graph = AdjList<NoLookup>;

40/// A graph that additionally answers `edge(s, t)` in O(1).
