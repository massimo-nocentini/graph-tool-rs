1//! Deterministic parallelism.
2//!
3//! Three things graph-tool's OpenMP layer gets wrong, all structural:
4//!
5//! * `parallel_loop_spawn` (`parallel_util.hh:438-446`) declares
6//!   `std::exception_ptr eptr{}` *outside* `#pragma omp parallel` and assigns
7//!   it *inside*, so every thread races on a refcounted handle. Four verbatim
8//!   copies live in `graph_properties_copy.cc`. Here the error is a **return
9//!   value** ([`try_det_reduce`]); there is no shared slot to race on.
10//! * `merge_split.hh:1131-1142` accumulates `log_sum_exp` under
11//!   `#pragma omp critical`, so the floating-point association order is the
12//!   thread interleaving and the result is not reproducible even at fixed
13//!   thread count. [`Plan`] fixes the chunk count and the fold order.
14//! * `parallel_rng.hh:56-61` returns `_rngs[tnum - 1]`, so results depend on
15//!   `OMP_NUM_THREADS`, and `get_rngs` (`:183-191`) caches streams in a
16//!   process-global map keyed on the *address* of the caller's generator and
17//!   never evicts -- so a freed generator whose address is reused inherits the
18//!   previous object's streams. [`Seed::split`] is keyed on the **chunk
19//!   index**.
