1//! # Implementation plan
2//!
3//! The skeleton in `crates/` compiles and its module tree is **complete**. No unit
4//! below needs to add a module, a `use` in a crate root, or a re-export: every
5//! public item the design calls for is already declared. Implementers fill
6//! `todo!()` bodies.
7//!
8//! Each `todo!()` in the tree is tagged with its unit number, so
9//! `grep -rn 'todo!("U5' crates` is the exact worklist for unit 5.
10//!
11//! ## Rules
12//!
13//! 1. **File ownership is disjoint and exhaustive.** A unit edits only the files
14//!    listed under *Owns*. If a unit believes it needs to touch a file it does not
15//!    own, that is a design error: stop and raise it against [DESIGN](crate::design)
16//!    rather than editing across the boundary.
17//! 2. **Crate roots are frozen.** The five `crates/*/src/lib.rs` files are owned by
18//!    **U-FINAL** and by nothing else. The module tree is already declared.
19//! 3. **Tests go in the unit's own file**, named after the unit, e.g.
20//!    `crates/gt-core/tests/u05_adjlist.rs`. Never in a shared test file.
21//! 4. **`cargo build --workspace` and `cargo clippy --workspace --all-targets
22//!    --all-features` must pass after every unit**, with zero warnings. They pass
23//!    now; keep them passing.
24//! 5. **A unit is not done because it compiles.** §16 of [DESIGN](crate::design) exists because
25//!    every source design said "verified by compiling it" and shipped a defect its
26//!    own claims denied. Each unit's acceptance test below is the minimum, not the
27//!    target.
28//! 6. `todo!()` bodies may be left in a file a unit owns *only* if the unit's
29//!    description says so (a few units deliberately land in two passes).
30//!
31//! ## Dependency order
32//!
33//! ```text
34//! U0 ──┬─> U1 ─┬─> U2 ─> U3 ─> U4 ─> U5 ─┬─> U6
35//!      │       │                          ├─> U7
36//!      │       ├─> U8 ─> U9 ─> U33        │
37//!      │       └─> U10 ─> U11             │
38//!      │             └──> U12             │
39//!      │                                  ├─> U13..U17   (gt-algo)
40//!      │                                  ├─> U18 ─> U19 ─> U20 ─> U21
41//!      │                                  │              └─> U22 ─> U23 ─> U24 ─> U25 ─> U26
42//!      │                                  ├─> U27 ─> U28, U29
43//!      │                                  └─> U30 ─> U31 ─> U32
44//!      └────────────────────────────────────────────────────────> U-FINAL
45//! ```
46//!
47//! U2–U5 are a chain (storage is one object). Everything after U5 parallelises
48//! widely: U6/U7, U13–U17, U18–U26, U27–U29 and U30–U32 are four independent
49//! streams.
50//!

83//! * `GraphId::fresh()` returns distinct values across 10 000 calls and from two

86//!   - `Bound::new` from a downstream crate → `E0624`.
87//!   - `Rev<Und<&AdjList>>` → `E0271`.
88//!   - `Und<&AdjList>::in_edges` → `E0599`.
89//!   - `&dyn GraphRef` → compile error (the trait is intentionally not a trait

92//!   These four are quoted in [DESIGN](crate::design) §14 and must not be allowed to regress.

96//! ## U2 — Adjacency block and the edge-id allocator
97//!
98//! **Owns:** `crates/gt-core/src/adj/mod.rs`, `crates/gt-core/src/adj/entry.rs`,
99//! `crates/gt-core/src/adj/block.rs`, `crates/gt-core/src/adj/alloc.rs`. **Tests:** `crates/gt-core/tests/u02_block.rs`.
100//!
101//! **Fills:** `Block::{get, insert_out, insert_in, remove_at, shrink}`,
102//! `EdgeIds::{alloc, release, compact}`.
103//!
104//! `insert_out` **must** be the O(1) push-swap of `graph_adjacency.hh:1192-1215`
105//! (push `entries[out_len]` to the back, overwrite the slot). An `insert` at the
106//! boundary is O(in-degree) and was measured quadratic; see [DESIGN](crate::design) §3.
107//!
108//! **Acceptance:**
109//! * `size_of::<Block>() == 32` and `size_of::<AdjEntry>() == 8`, asserted.
110//! * Property test: random `insert_out`/`insert_in`/`remove_at` sequences against a
111//!   naive `(Vec<AdjEntry>, usize)` model; after every op the out-half and in-half
112//!   contents match the model as multisets, and every returned `Moved` names an
113//!   entry that really is at `to`.
114//! * `EdgeIds`: `live() == next() - free.len()` after every op; `alloc` after
115//!   `release` reuses the released id; `compact()` is a permutation.
116//! * **Benchmark asserting non-quadratic `insert_out`**: 10k/20k/40k/80k
117//!   out-insertions onto a vertex with that many pre-existing in-edges must scale
118//!   within 2.5× per doubling, not 4×.
119//!

122//! ## U3 — The edge slot table and the `(s,t)` lookup
123//!
124//! **Owns:** `crates/gt-core/src/adj/index.rs`.
125//! **Tests:** `crates/gt-core/tests/u03_index.rs`.
126//!
127//! **Fills:** `EdgeSlots::{endpoints, locate, on_insert, on_move, on_remove,
128//! rebuild}`; `EHash::{on_link, on_unlink, find, rebuild}`.
129//!
130//! `locate` performs the identity check **itself**, against the half named by
131//! `end`, bounds-checked. A caller-side guard passes whenever the two halves share
132//! a position; see [DESIGN](crate::design) D12.
133//!
134//! **Acceptance:**
135//! * `size_of::<EdgeSlot>() == 4 * size_of::<Raw>()`.
136//! * `locate(blocks, id, Out)` and `locate(blocks, id, In)` disagree about the
137//!   block whenever `src != tgt`, and agree when `src == tgt`.
138//! * `locate` returns `None`, never panics, for a released id, an out-of-range id,
139//!   and a slot whose block entry has been overwritten.
140//! * `EHash` after a random link/unlink sequence equals a brute-force
141//!   `HashMap<(V,V), Vec<E>>`; `rebuild` reproduces the incremental state exactly.

162//! ## U5 — `AdjList`: the two splice primitives
163//!
164//! **Owns:** `crates/gt-core/src/adj/list.rs`.
165//! **Tests:** `crates/gt-core/tests/u05_adjlist.rs`.
166//!
167//! **Fills:** everything except `new`/`with_lookup`, which are done. In
168//! particular `splice_in`, `splice_out`, `add_edge`, `remove_edge`,
169//! `clear_vertex_where`, `swap_remove_vertex`, `find_edge`, `validate`.
170//!
171//! `splice_out` must re-locate the in-half **after** splicing the out-half; the
172//! borrow checker enforces the ordering, but the code must not work around it.
173//! `clear_vertex_where` uses `self.scratch`, not a fresh `Vec`.
174//! `swap_remove_vertex` relabels by unlink-then-relink so both index hooks fire
175//! for both directions.
176//!
177//! **Acceptance:**
178//! * **Model-based proptest, the centrepiece of this unit.** 2 000+ cases ×
179//!   {`NoLookup`, `EHash`}, ≤ 6 vertices, sequences of up to 16
180//!   `add_edge`/`remove_edge`/`clear_vertex`/`clear_vertex_where`/`swap_remove_vertex`
181//!   including self-loops and parallel edges. After **every** operation:
182//!   `validate()` is `Ok`; `num_edges()` matches a `BTreeMap<EdgeId,(V,V)>`
183//!   reference; the full sorted out-half **and in-half** match the reference.
184//!   (Checking only the out-half is what let one source design ship a `validate`
185//!   that never inspected the in-half at all.)
186//! * `clear_vertex` on a vertex with a self-loop plus one other out-edge, under a
187//!   predicate matching only the self-loop, decrements `num_edges()` by exactly 1.
188//!   This is defect #1.
189//! * `remove_edge` of an id obtained from `find_edge(t, s).reversed()` behaves
190//!   identically to `remove_edge` of the forward id (there is no orientation to
191//!   get wrong; assert it).
192//! * Allocation assertion: 10 000 `clear_vertex` calls on a 20k/160k graph perform
193//!   **zero** allocations after warm-up.

210//! ## U7 — The view algebra
211//!
212//! **Owns:** `crates/gt-core/src/view/mod.rs`,
213//! `crates/gt-core/src/view/undirected.rs`,
214//! `crates/gt-core/src/view/reversed.rs`,
215//! `crates/gt-core/src/view/filtered.rs`.
216//! **Tests:** `crates/gt-core/tests/u07_views.rs`.
217//!
218//! **Fills:** `MaskFilter::{keep_vertex, keep_edge}`; `Filtered::{new, masked,
219//! out_degree, degree, in_degree}`; `Filtered`'s `Endpoints` impl; the `Iterator`
220//! impls for `FilterIncident`, `FilterEdges`, `FilterVertices`.
221//!
222//! `Filtered::new` and `FilterEdges` must both go through `keeps_edge`. Two
223//! predicates is how `num_edges()` comes to disagree with `edges().count()`.
224//!
225//! **Acceptance:**
226//! * On the path `0→1→2`: `g.undirect().out_edges(1)` yields `other ∈ {0, 2}` —
227//!   **never 1**. This is defect #14 and it is the single most important assertion
228//!   in this unit.
229//! * `g.reverse().out_edges(v)` equals `g.in_edges(v)` as a multiset, and is

232//!   `num_edges() == edges().count()`, on a graph with a filter that removes
233//!   vertices, edges, and both.
234//! * `vertex_bound()` is unchanged by filtering; `num_vertices()` is not.
235//! * `Filtered::masked` with a mask shorter than the bound returns
236//!   `Err(ShortMask)`, and a mask validated against graph A cannot be used with
237//!   graph B (borrowck or `Err`, assert which).
238//! * `size_of` assertions for all six views ([DESIGN](crate::design) §11).
239//! * trybuild: `g.undirect().reverse()` → `E0599`.

439//! ## U19 — The delta buffer
440//!
441//! **Owns:** `crates/gt-inference/src/delta/mod.rs`,
442//! `crates/gt-inference/src/delta/entry.rs`,
443//! `crates/gt-inference/src/delta/buf.rs`. **Tests:** `crates/gt-inference/tests/u19_deltabuf.rs`.
444//!
445//! **Fills:** `DeltaBuf::{begin, touch, touch_dyn, delta_of, me_of}`.
446//!
447//! `begin` resets exactly the slots recorded in `self.slots` and must be correct
448//! **regardless of the order** relative to the move key — unlike `EntrySet::clear`
449//! (`entries.hh:169-176`), which re-derives addresses from `_rnr`.
450//!
451//! **Acceptance:**
452//! * Property test: random `touch` sequences; `delta_of(s, t)` equals a
453//!   `HashMap<(Group,Group), W>` reference; `entries()` contains each touched pair
454//!   exactly once.
455//! * `begin` with a **different** move key after a previous recording leaves no
456//!   residue: every field slot is null and `delta_of` is zero for every pair.
457//! * `begin` is O(#entries): assert the number of field-slot writes, not the
458//!   wall clock.
459//! * `touch_dyn` on a pair touching neither endpoint returns `Err(OutOfPlane)` and
460//!   leaves the buffer unchanged. This is defect #4.
461//! * `size_of::<DeltaBuf<Undirected, i64>>() < size_of::<DeltaBuf<Directed, i64>>()`
462//!   — the undirected buffer holds two field vectors, not four empty ones.
463//!
